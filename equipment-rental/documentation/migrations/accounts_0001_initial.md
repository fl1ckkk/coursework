## Мета

Створити власну модель користувача з предметною роллю. Її задано до першого
`migrate`, бо замінити модель користувача на вже робочій базі в Django складно.

## Зміни в схемі

Таблиця `accounts_user`: усі стандартні поля користувача Django
(`username`, `password`, `email`, `is_staff`, `is_active` тощо) і додатково:

| Поле | Тип у БД | Значення за замовчуванням |
|---|---|---|
| `role` | `varchar(16) NOT NULL` | `client` (задається Django) |
| `phone` | `varchar(20) NOT NULL` | порожній рядок |

Службові таблиці зв'язку з групами й правами Django:
`accounts_user_groups`, `accounts_user_user_permissions`.

## SQL (скорочено)

```sql
CREATE TABLE "accounts_user" (
  "id" bigint NOT NULL PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
  "password" varchar(128) NOT NULL,
  "username" varchar(150) NOT NULL UNIQUE,
  ...
  "role" varchar(16) NOT NULL,
  "phone" varchar(20) NOT NULL
);
CREATE TABLE "accounts_user_groups" (...);
CREATE TABLE "accounts_user_user_permissions" (...);
```

## Відкат

```bash
python manage.py migrate accounts zero
```

Видаляє таблиці користувачів разом з даними. Спершу потрібно відкотити
`bookings`, бо бронювання посилаються на користувачів.
