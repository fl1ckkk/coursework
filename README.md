# Оренда обладнання з календарем доступності

Курсова робота з дисципліни «Веб-технології та веб-дизайн» (варіант 12).

Вебсистема прокату обладнання. Клієнт вибирає позицію в каталозі, дивиться
календар доступності конкретних екземплярів, бронює екземпляр на період,
одразу бачить вартість, може продовжити або скасувати оренду. Коректна заявка
підтверджується автоматично. Менеджер видає й приймає обладнання (за запізнення
нараховується доплата) і веде каталог в адмінці.

Головне правило: **активні бронювання одного екземпляра не можуть перетинатися
в часі** з урахуванням технічної перерви між орендами. Його перевіряє сама база
даних, тому воно діє і для одночасних запитів.

Детальна документація: [`documentation/`](documentation/README.md).

## Запуск

### 1. Отримати код і встановити залежності

```bash
git clone https://github.com/fl1ckkk/coursework.git
cd coursework
python -m venv .venv
# Windows:      .venv\Scripts\activate
# Linux/macOS:  source .venv/bin/activate
pip install -r requirements.txt
```

Якщо в Windows активацію `.venv` заблоковано політикою безпеки, активувати
середовище не обов'язково: замість `python` викликайте `.venv\Scripts\python.exe`,
наприклад `.venv\Scripts\python.exe -m pip install -r requirements.txt`.

### 2. Налаштувати середовище

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

Відкрийте `.env` і задайте `DJANGO_SECRET_KEY` та пароль бази даних.

### 3. Підготувати базу даних

Варіант А: PostgreSQL у Docker (значення беруться з `.env`):

```bash
docker compose up -d
```

Варіант Б: встановлений PostgreSQL. Створіть користувача й базу, назви яких указані в `.env`:

```sql
CREATE USER rental WITH PASSWORD 'ваш-пароль' CREATEDB;
CREATE DATABASE rental OWNER rental;
```

Право `CREATEDB` потрібне лише для запуску тестів: Django створює окрему тестову базу.

### 4. Застосувати міграції та завантажити демо-дані

```bash
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser   # для входу в /admin/
```

Користувач, створений `createsuperuser`, має доступ до адмінки, але на сайті
за замовчуванням є клієнтом. Щоб він бачив панель «Заявки», в адмінці відкрийте
«Користувачі» → цей користувач → «Роль» = «Менеджер».

`seed_demo` створює синтетичні демо-дані (усі з паролем `demo-pass-123`):

- менеджера `manager` і 12 клієнтів (`client1`, `client2`, `andrii`, `sofiia`, `dmytro` та ін.);
- каталог із 20 позицій у 7 категоріях (60 екземплярів) з тарифами й технічними перервами;
- історію близько 300 бронювань за останні два місяці й на півтора місяця вперед:
  повернені (частина із запізненням і доплатою), скасовані, видані, майбутні;
- у порожній базі ще й сценарні бронювання для демонстрації панелі менеджера
  (видача сьогодні, не забрали, прострочено, екземпляр ще не повернули).

Повторний запуск безпечний: нічого не дублюється, а на базі з уже наявними
бронюваннями конфліктні записи просто пропускаються.

### 5. Запустити

```bash
python manage.py runserver
```

- Каталог: http://127.0.0.1:8000/
- Адміністрування: http://127.0.0.1:8000/admin/

### 6. Запустити тести

```bash
python manage.py test
```

Навантажувальне тестування: [`documentation/load-testing.md`](documentation/load-testing.md).

## Структура

```
config/          налаштування Django, маршрути
accounts/        користувачі й ролі (клієнт, менеджер)
catalog/         типи обладнання, екземпляри, тарифи, сторінки каталогу
bookings/        бронювання, журнал подій, бізнес-правила (services.py)
templates/       HTML-шаблони
static/          стилі (світла й темна теми, адаптивна верстка)
loadtest/        сценарії навантажувального тестування (Locust)
documentation/   документація проєкту та міграцій
```
